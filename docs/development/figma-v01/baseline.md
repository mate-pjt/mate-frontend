## 검증 증거의 경계

- 조사 시 Node 22.20.0에서 계약/구조 테스트 **62건·8파일**, lint를 통과했다. 격리 snapshot의 **webpack 빌드**도 통과했다. 기본 Turbopack은 격리본의 외부 `node_modules` symlink 제약으로 실패했으며 원본 작업트리에서 기본 빌드를 다시 실행한 결과는 아니다.
- 합성 데이터로 7개 공급원과 주요 브라우저 흐름을 확인했다. 실제 API mutation은 실행하지 않았다. 모든 Figma 상태의 실행·픽셀 비교를 완료한 것도 아니다.
- mock 브라우저의 API/OAuth/업로드/첨부 외부 요청은 관찰/차단 0건이었다. 격리 dev 서버에서 외부 fetch 시도 **1건이 가드에 차단**됐고 목적지는 기록되지 않았다. 빌드 fetch는 0건이었다. 서버까지 포함한 전체 외부 시도 0건으로 표현하지 않는다.
- 기존 QA 기록은 124개 사례 중 25 통과·92 대기·7 차단이었다. 정적 FAQ 사례도 포함돼 실제 API 완료율로 계산할 수 없다. 조사로 기존 실제 통합 대기를 통과로 바꾸지 않았다.
- 현재 실제 서버의 실행 SHA·모든 fixture·Mailpit 접근 가능 여부는 이 보고서로 입증되지 않는다. [PREP-01](tasks/PREP-01.md)에서 재개 조건을 점검한다.
- 이번 WBS 문서화의 검사/리뷰는 [DOC-001 검토 기록](reviews/DOC-001.md)에 따로 남긴다. 위 앱 테스트 결과는 과거 조사 증거이며 문서화 과정에서 새로 실행한 앱 테스트가 아니다.

## 정책·API 근거와 미결 사항

1. 공고 등록, 받은 알림 이력, 맞춤 이메일은 다른 기능이다. 현행 중앙 정책은 **08:30 맞춤 이메일·공고별 내부 알림**을 구분한다. 야간 수신/전역 공고 토글을 Figma만 보고 복원하지 않는다. 대체 이메일 기준은 당시 중앙 문서의 3분/60초와 mock/개발 가이드의 10분/30초가 달랐다. API UI는 서버 반환 시각을 사용한다. [POL-19](tasks/POL-19.md) → [DEV-41](tasks/DEV-41.md).
2. 중앙 정책은 변경 신호 수신 → REST 재조회를 설명한다. 구현할 전송 방식/인증·재연결 계약은 착수 때 확인한다. [POL-05](tasks/POL-05.md) → [DEV-07](tasks/DEV-07.md).
3. 당시 backend dev 소스의 `GET /api/v1/me/bid-notice-alerts`는 category 필수, `GENERAL/CORRECTED/CLOSED/RESULT_COMPLETED`만 지원했다. `GENERAL`은 전체가 아니고 `counts.total`만으로 전체 목록을 구성할 수 없다. 소스 관찰은 배포 Swagger 반영 증명이 아니다. [POL-03](tasks/POL-03.md)의 차단/재개 조건을 따른다.

정책 원문: [mate-docs 알림 정책 · main](https://github.com/mate-pjt/mate-docs/blob/main/docs/domain/notification/overview.md). 이 링크는 움직이는 참조다. 조사 응답의 `c649b3092157a091f1be54d92195e65622150ac9`는 **파일 blob SHA(내용 지문)**이며 commit ref가 아니다. 당시 정책 내용은 로컬 조사 산출물의 `evidence/github-policy.json`에 보존했다. 후속 구현 전 최신 소유 소스를 확인한다. API 원문 경로는 [Controller](https://github.com/mate-pjt/mate-backend/blob/dev/mate-api/src/main/java/kr/co/mate/mate_api/adapter/input/web/bidnoticealert/AccountBidNoticeAlertController.kt)와 [Category](https://github.com/mate-pjt/mate-backend/blob/dev/mate-api/src/main/java/kr/co/mate/mate_api/domain/bidnoticealert/AccountBidNoticeAlertCategory.kt)이며 이 dev 링크도 움직이는 참조다. 당시 응답 snapshot은 로컬 조사 산출물의 `evidence/github-alert-controller.json`에 보존돼 있다.

정식 약관/동의 버전·계정/탈퇴·회사 권한/문서 생명주기/통합·콘텐츠/문의·네이버 지원은 후속 결정 작업이다. WBS에 기록했다는 사실은 승인/계약 확정을 뜻하지 않는다. 기존 승인 근거가 있으면 그대로 적용하며 같은 승인을 반복 요청하지 않는다.

- [plan.md](../../ai-context/plan.md)의 과거 완료 기록은 당시 범위·검증의 이력이다. 현재 79개 항목 진행 상태는 WBS를 우선 읽는다. 기존 QA 문서의 대기/차단과 승인 예외는 유지한다.
- 가입 중 인증/희망금액 표시(O08)와 가입 후 회사 대시보드(M04), 초대 수신(O10)과 발송(T02), 가입 업로드(O07)와 서류함(F01~04), 회사 소속 신청(O05)과 회사 간 통합(G01~03)은 서로 다른 완료 범위다.
- `3162:51281`은 회사 시작 선택 화면이며 신청 대기 화면이 아니다. 최상위 `resign_popup`(`3296:55798`)은 실제 문구상 통합 요청 자격 확인이다. 탈퇴로 오분류하지 않는다.
- 공용 업로드 팝업이 제품에 미연결이어도 별도 구현된 가입 업로드를 미구현으로 바꾸지 않는다. 비밀번호 팝업이 있다고 비밀번호 로그인을 추가하지 않는다.
