## 착수 전 Implementation Brief / 설계 Gate

2026-10-30 사용자 Task 요청과 아래 QA-03 전용 제한 종료 답변으로 확정했다. 원래 통합 완료 기준은 위 체크리스트와 DETAIL-01~09에 보존한다.

- 요구사항: 이미 구현된 공개 상세 3종·분류·개찰/참여업체·물품·첨부의 실제 QA. 현재 데이터로 가능한 검증 후 잔여 차단을 보존하고 제한 종료·Git 전달한다. 전체 통합 PASS와 구분한다.
- 성공 기준: 실제 공개 GET과 Next/브라우저의 관찰을 대응하고 실행 식별자·시각·화면·비식별 증거·복구·남은 fixture/배포 한계를 기록한다. 미실행/부분 확인을 case 전체 통과로 바꾸지 않으며 두 리뷰 후 인계한다.
- 범위: 현재 정상 용역 공고의 상세/목록 진입·KST·nullable 금액/숫자·원 전환·공유·키보드·1440/390/320px 화면, 공개 첨부 메타데이터/관련 공고/결과 GET·404·소유 로컬 Next 프로세스 한정 본문/독립 섹션 연결 실패와 해제·복구. 실제 backend 오류 응답과 로컬 연결 실패를 분리한다.
- 제외: 제품 코드 구현/결함 수정, fixture/DB 생성·변경, 로그인/가입/업무 mutation, 공유 서비스 장애/운영·배포, 새 API/정책/라이브러리. 첨부는 3건이 있지만 승인된 합성 자료임이 확인되지 않아 파일 내용 열람·다운로드·보관은 제외하며 DETAIL-06 차단으로 추적한다. `originalNotice.available=false`지만 현행 mapper는 `header.noticeUrl`을 사용해 나라장터 링크를 표시한다. HTTPS 호스트·target/rel만 확인하고 외부 본문 접근은 하지 않는다.
- 확인한 근거/패턴: AGENTS와 세 Skill, 기준선·WBS/coverage·workflow/task-cycle, PREP-01 준비표·QA-02 승인/종료와 QA-04 main 반영, 공통 context/data-access·package/scripts, 상세 Page·공개 bids server·HTTP/DTO/mapper·content/actions/amounts, verifier·PR 템플릿. 서버 공개 GET·독립 section·mock fallback 없음·UI/API 페이지 경계를 유지한다.
- 수정 대상/영향: 이 기록·WBS·`docs/qa/bid-detail.md`·QA 인덱스 상세 한 행·`reviews/QA-03.md`의 Markdown 다섯 파일. 소스/테스트/설정/패키지/기준선/다른 Task는 변경하지 않는다. 실행 helper·비식별 증거는 저장소 밖 이번 대화의 `qa-03-bid-detail/`에 보존한다.
- 단계: main/선행/clean 확인 → 공개 준비 조회 → 승인 범위 확정/기록 → 실제 Next·브라우저 QA → 소유 프로세스 실패/복구·정리 → 문서·보존 검사/Documentation Update Check → read-only verifier·AI Review → 목적별 문서 커밋·PR/head CI·merge/main FF.
- 검증: Node 22.20.0의 실제 `pnpm test`, `pnpm lint`, `pnpm build`, `git diff --check`와 실제 Next/브라우저. 문서 링크·79 원본/99 Task·의존/상태·보호 파일 지문·타 Task/QA 보존도 검사한다. Storybook·공유 UI·공급원 변경이 없어 build-storybook·추가 구성별 로컬 build는 제외한다. mock/HTTP 대역은 실제 API PASS의 근거로 대체하지 않는다.
- 가정/위험: ALL에는 정상 SERVICE 1행만 확인됐다. 복수 분류·상태 변경·개찰/참여업체·물품 페이지/관련 카드 fixture가 부족하다. backend 현재 실행 SHA/이미지 대응은 미확인이며 성공 배포 이력과 구분한다. `.env` 내용 읽기는 차단하고 공개 api/local 설정만 명시한다. 기관 담당자·전화·이메일·첨부 파일명·인증정보 원문을 수집/출력하지 않고 안전한 범위의 화면만 캡처한다.
- blocking ambiguity: 아래 답변으로 이번 종료 범위는 해소. 합성 파일 사용·현재 실행 버전/전체 fixture는 미확인으로 남기며 독립 실행 가능한 검증을 진행한다. 소유 프로세스 실패 제어는 로컬/가역 검증 범위다.
