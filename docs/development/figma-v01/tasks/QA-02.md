## 착수 전 Implementation Brief / 설계 Gate

2026-10-30 사용자 Task 요청·최초 두 답변과 BID-14 최소 수정의 후속 답변으로 확정했다. 최초 전체 통합 기준은 위 체크리스트와 기존 BID-01~16에 보존한다.

- 요구사항: 기존 공개 목록·검색·기본/preset 필터·페이지의 실제 API QA. 현재 데이터로 가능한 검증과 후속 승인된 BID-14 한 파일 최소 수정·정리·문서/Review Gate를 마친 뒤 승인된 제한 종료·Git 전달을 수행한다.
- 성공 기준: 실행한 사례의 화면·URL·실제 API 요약과 결과를 대응하고, 없는 정렬/종류/결과/분류/다중 페이지/경계 데이터를 차단으로 남긴다. 실행 환경·시각·식별자·비식별 증거·정리·잔여 재개 조건 및 다음 Task 하나를 기록한다. 전체 통합 PASS와 이번 제한 종료 PASS를 구분한다.
- 범위: BID-01~16의 현재 공개 GET·실제 Next/Chrome·검색/초기화/URL 복귀·기본/preset 필터·범위 밖 페이지·빈 결과·모바일/키보드. QA-A 사용자 직접 로그인/refresh/종료 로그아웃, 소유 로컬 프로세스의 목록/metadata fetch 연결 실패·해제와 재시도.
- 제외: fixture/DB 생성·수정, 신규 가입, 회사/개인 필터 저장·초기화·구독 등 업무 mutation, 공유 서비스 장애/운영/배포, 고급 필터·낙찰금액·맞춤 목록 개발, 새로운 API/정책/라이브러리. 실제 서버 4xx/5xx와 프로세스 한정 연결 실패를 구분한다.
- 확인한 파일/패턴: 공통 context와 data-access, PREP-01 준비표, QA-01 예외/QA-04 종료, `src/app/bids/{page,error}.tsx`, bids server/HTTP/DTO/mapper, 목록 client/model/search/table/toolbar, `src/data/config.ts`, 실제 package scripts·workflow·verifier·PR 템플릿. 서버 공개 GET·metadata 코드 변환·KST·API 0-based/UI 1-based·URL 상태·mock fallback 없음의 기존 패턴을 유지한다.
- 수정/영향: WBS·이 기록·`reviews/QA-02.md`·`docs/qa/bid-list.md`·QA 인덱스 목록 한 행, Markdown 다섯 파일과 후속 승인된 `src/app/bids/error.tsx` 한 파일. 실행 증거/검증 helper는 저장소 밖 현재 대화의 `qa-02-bid-list` 디렉터리에 보존한다. 목록 오류 재조회 외 runtime/package/설정/다른 Task/기준선/매핑 변경 없음.
- 단계: 선행/main/clean 확인 → 공개 3 view×3 종류·metadata 대조 → 검색/기본/preset/URL·페이지/0건·모바일/키보드 → 로컬 실패·복구 및 BID-15 → 승인된 한 파일 재시도 수정/재검증 → 로그아웃/프로세스·탭/실패 제어 정리 → 문서 검사/두 리뷰 → 목적별 커밋/PR·head CI/정상 merge/main FF.
- 검증: Node 22.20.0의 실제 `pnpm test`, `pnpm lint`, `pnpm build`, `git diff --check`·실제 Next/Chrome. 링크·79 ID/99 Task·기존 QA/다른 WBS 행·보호 파일 지문·변경 범위·승인/차단/상태 일관성도 검사한다. 공용 UI/Storybook 변경이 없어 build-storybook은 제외. mock/HTTP 대역/실제 API 결과를 분리한다.
- 가정/위험: Next 16.2.9의 `unstable_retry`는 설치된 framework 타입·구현에 존재하며 refresh와 reset을 함께 수행한다. 버전 갱신 시 이 연동의 회귀 검증이 필요하다. 현재 데이터는 ALL/SERVICE 1행이며 다른 조합 0행이다. sparse 데이터로 복수 정렬/페이지/결과를 통과시키지 않는다. 최근 backend 배포 성공은 현재 실행 SHA의 증명이 아니므로 미확인을 명시한다. `.env` 내용 로딩을 차단하고 공개 api/local 입력만 명시하며 인증 query/header/body·token/cookie·개인정보를 수집하지 않는다.
- blocking ambiguity: 아래 세 사용자 답변으로 실행·종료/정리·최소 수정 범위 해소. 새 제품/API 정책 결정 없음. 문서 정합성은 관련 범위 context-audit로 점검한다.
