- 요구사항/성공 기준: 현행 초대 수신 흐름과 AUTH-16을 대조하고 필요한 fixture·승인·복구·실행 근거를 특정한다. 실제 미실행/차단을 통과와 분리하고 기존 17개 case·선행 예외·기준선을 보존한다. 문서 검증·read-only verifier·AI Review 통과 후 승인된 Git 전달을 수행한다.
- in scope: QA-08/PREP 준비표·QA-04/QA-07 결정·AUTH-16·현행 invitation UI/Repository/관련 계약 테스트의 읽기 전용 점검, 차단/재개 조건·QA/WBS/검토 기록 갱신.
- out of scope: 실제 API(GET 포함)/OAuth·브라우저·신규 가입·초대 발송/소비·membership/fixture 변경·복구 실행·서비스 운영/배포. 발송 관리(T02)·수락 후 팀원 목적지(O11)·다른 기능 구현, 라이브러리/정책/API 계약 변경도 제외한다. 실제 링크·초대값·이메일·인증값·환경파일을 읽거나 받지 않는다.
- 확인한 파일/패턴: AGENTS, feature-workflow/ai-review/context-audit, WBS/workflow/task-cycle/baseline/coverage, base/architecture/data-access/plan/harness/ai-failures, QA 공통 규칙·PREP 준비표·AUTH-16, 초대 화면과 company 공개 client/contracts/HTTP 및 기존 mock 테스트 경계. 현재 상태는 WBS 한 곳, 실제 사례는 auth QA에 누적한다.
