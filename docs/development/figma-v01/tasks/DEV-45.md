## 2026-11-23 · POL-22 정책 인계와 재개 조건

- **선행**은 [POL-22의 사용자 결정](POL-22.md#pol-22-brief)과 [DEV-08 회사 조회](DEV-08.md)다. DEV-08의 배포·합성 자료/권한별 계정 차단을 적용한다. 첫 행동은 선행 상태와 아래 서버 계약을 대조해 DEV-45 자체 요구사항 Gate를 작성하는 것이다.
- **허용할 사용자와 데이터**는 백엔드·정책 소유자가 활성 소속의 역할별/leaf별 가져오기와 희망금액 포함 범위, 회사 합치기 제한을 함께 확인해야 한다. `canImportCompany`의 현행 의미는 회사 원천 존재다. 기능 노출에는 소유 결정과 그 결정을 서버가 적용한다는 근거가 필요하다. 기존 `COMPANY_DEFAULT` 응답의 노출 범위도 소유자 확인 자료로 사용한다.
- **전부 결측 시 기존값 보존**은 현재 소속·투영·권한을 확인하는 변경 경계에서 서버가 보장해야 한다. 현재 POST는 활성 회사의 빈 투영도 `SAVED`로 저장할 수 있다. 전부 결측에서도 기존·미저장 계정 모두에 쓰기가 발생하지 않는 소유 계약과 응답을 먼저 확보한다. 일부 결측은 [필드별 정책](POL-22.md#pol-22-contract)대로 전체 교체를 검증한다.
- **확인 이후 소속 변경**은 화면에서 감지할 수 있는 변경과 서버 도착 전후의 경쟁을 모두 포함한다. 개인 `expectedVersion`만 보내는 현행 POST의 재검사는 서버가 최초로 읽은 소속부터 보호한다. 확인 시점의 회사/소속과 다른 요청을 거절하고 기존 값을 보존하는 서버 경계를 확인한다. 요청 형태와 오류 코드는 자체 Gate에서 소유 계약에 맞춰 정한다.
- **화면**은 전체 교체와 즉시 계정 저장을 명시하고 취소 시 무쓰기를 보장한다. 목록은 저장 뒤에도 같은 URL·표시 조건을 유지하고, 사용자가 `내 맞춤`을 눌러 최신 읽기로 별도 적용한다. 정확한 투영값 미리보기, 목록의 일반 저장 보조행 재도입 및 기존 화면 승인의 신규 적용은 범위 밖이다. 노출 가능한 화면·진입 위치와 권한/빈 값/충돌 상태의 시안·키보드/모바일 기준은 자체 Gate에서 승인 근거를 확인한다.
- **검증**은 [CIMP QA 계획](../../../qa/personal-bid-filter.md#pol-22-company-import-qa)을 사용한다. 현재 프론트/백엔드 실행 식별자·게시 명세·실제 응답을 구분하고, 회사 소속/권한/잠금 상태별 합성 데이터, 전부 결측/부분 결측/전체 투영, 두 탭·복수 계정, 안전한 실패와 개인 저장값·회사 원본의 확인·복구 권한을 확보한다. 미저장 계정의 `null` 버전 복원이 일반 reset으로 가능하다고 가정하지 않는다. QA-10 기존 12차단은 별도다. 이번 인계는 DEV-45 구현, 실제 API 실행 또는 로컬 선행 승인이 아니다.
