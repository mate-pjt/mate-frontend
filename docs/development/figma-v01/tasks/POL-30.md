## 작업 정의

- 유형: 정책 결정. 원본: D09. 선행: [QA-17](QA-17.md)의 고정 정책/백엔드 대조.
- 목적: 관련 공고를 조회하는 **기준 공고의 마감/취소**와 결과로 추천하는 **후보 공고의 마감/취소**에 서로 다른 규칙이 필요한지 소유 원문과 현재 계약으로 확정한다.
- 현재 충돌: 중앙 matching-and-related-notices.md §6은 취소/마감 기준 공고에서 관련 공고를 반환하지 않는다고 하고, §10의 과거 공고 단락은 마감/취소 기준 공고도 비교 자료로 쓸 수 있다고 한다. 같은 고정 문서 안의 충돌이다.
- 백엔드 dev의 RelatedBidNoticeQueryService는 공개/삭제·분류 identity를 확인하고 기준 공고 마감/취소로 조기 반환하지 않는다. 후보의 진행 상태는 별도 조회에 적용한다. 이는 현재 소스 관찰이며 실제 실행/제품 결정 승인이 아니다.
- 추천: 현재 소스와 §10처럼 과거 기준 공고/진행 후보의 규칙을 분리하되 정책 소유자의 확인과 명시적 원문 정리를 남긴다. 추천을 승인으로 간주하지 않는다.
- 제외: 제품/중앙 저장소 무단 수정, 실제 업무 API 변경·외부 메시지·commit/push/PR/배포. 관련 공고 mock 수정은 [DEV-61](DEV-61.md)이 소유한다.

## 관련 공고 정책 v1 · 2026-11-12

기준 공고는 사용자가 현재 상세에서 보고 있는 공고이고, 후보 공고는 관련 공고 카드로 보여줄 다른 공고다. 기준의 업종·품목 사실을 이용해 같은 업무 유형의 후보를 찾는다. 마감·취소된 기준 공고도 탐색 출발점으로 사용하되, 결과 후보에는 아래의 현재 상태 조건을 적용한다. 관련성 점수·회사 맞춤 조건·전체 참가 자격 판정은 이 조회의 계약에 없다.

### 기준 공고의 상태

| 상태/입력 | 관련 공고 조회 기준 | 근거/구분 |
| --- | --- | --- |
| 공개·미삭제·정상, 유효한 업종/품목 있음 | 공식 사실로 후보 조회 | 현재 source 계약 유지 |

| 공개·미삭제·취소, 마감과 취소가 함께 있는 경우 | 공식 사실로 후보 조회 | 사용자 확정: 취소된 기준도 탐색 자료로 사용 |
| 공개·미삭제·마감시각 없음 | 공식 사실로 후보 조회 | source의 시간 결측만으로 차단하지 않음 |
| 미공개·삭제·미존재 | 같은 공고 없음404 | 공개/존재 경계 유지. 비교 facts를 읽기 전에 공개 확인; 빈 목록으로 숨기지 않음 |
| 물품/용역의 유효한 형식이지만 해당 공고에 없는 선택 분류 | 분류 없음404 | 다른 공고의 분류를 가져오거나 기본1로 바꾸지 않음 |
| 잘못된 분류 형식 또는 공사에 분류 query 지정 | 입력 오류400 | canonical은 `0` 또는 선행0 없는 최대50자리 ASCII 양의 정수 문자열. trim/임의 숫자 변환 없음 |
| 물품/용역의 분류 query 생략 | 전체 분류의 활성 품목 범위 | 선택 분류가 있으면 그 분류의 활성 품목만 사용; 용역의 최종 업종 집합은 공고 전체 기준 |
| 적용 가능한 공식 업종/품목 집합 없음 | 정상 빈 Slice, relationType=null | 존재/공개/분류 검증은 통과했지만 비교 기준이 없음 |
| 공식 비교 기준은 있으나 일치하는 현재 후보0건 | 정상 빈 목록, 적용 relationType 유지 | 기준 부재와 결과0건을 구분. 다른 유형/코드로 채우지 않음 |

ID/page/size 등 요청 검증 오류는 현재400 계약을 유지한다. 공개 확인/분류 소유 검증과 source 상태 identity 검산을 거친다. 서버 저장 상태의 identity 불일치500은 정상 빈 결과나 사용자404로 바꾸지 않는다. 이 표는 서비스/컨트롤러의 기존 입력·오류 경계를 설명하며 혼합된 잘못된 입력의 새 오류 우선순위를 만들지 않는다.

### 후보 공고의 상태

### 일치·표시 계약의 유지

- 공사는 최종 publication 업종 코드, 물품은 세부품명번호 → 없으면 품목분류번호, 용역은 최종 업종 → 없으면 세부품명 → 없으면 품목분류의 첫 non-empty 집합 하나만 사용한다. 직접/공식 허용업종을 포함한 최종 집합의 정확 코드 일치이며 이름 유사도·접두사·일부 품목별 낮은 우선순위 혼합은 없다.
- 품목 source는 삭제되지 않은 품목과 선택/전체 분류 범위를 따른다. target는 동일 업무 유형의 실제 일치 품목/분류를 사용한다. canonical 분류의 숫자 의미 순서는 길이/사전식 기준으로 보존하며 긴 번호를 부정확한 Number로 변환하지 않는다.
- 공고 게시시각 내림차순·null 마지막·동시각 ID 내림차순, 자기 제외/공고 중복 제거를 유지한다. API는0-based Slice·기본 size20/1~100이며 프론트 상세는 page0/size3으로 최대3카드다.3카드를 전체 후보 수로 설명하지 않는다.
- 카드 사업금액은 추정가격+VAT가 모두 있을 때만 제공하고 한쪽 결측이면 null이다. 기초금액/예산으로 대체하지 않으며 지역·금액 결측이나 차이로 후보를 제외하거나 점수화하지 않는다.
- 조회 때의 Clock과 저장된 후보 상태로 판단한다. 화면 자동 polling/새 추천 점수·API/DTO 확대는 이번 결정 범위에 없다. 내부 프론트 모델에 없는 relationType/hasNext를 mock 공개 계약에 추가하라는 요구도 아니다.

§6의 해당 두 문장 교체안:

> 사용자에게 공개된 삭제되지 않은 기준 공고는 마감되거나 취소됐어도 공식 업종·품목을 찾는 기준으로 사용할 수 있다. 기준 공고의 마감·취소 상태는 관련 후보의 현재 상태와 별도로 판단한다.

§10의 과거 공고 단락 중 삭제/비교 사실 관련 문장 교체안:

> 기준 공고가 존재하지 않거나 삭제·미공개라면404로 처리한다. 공개된 유효한 기준 공고에 비교할 공식 업종·품목이 없으면 정상 빈 목록을 보여준다. 비교 기준은 있지만 같은 기준의 현재 후보가 없는 경우에도 빈 목록을 보여준다.

§11의 마감 조건 정정안:

> 후보의 마감시각이 현재 조회시각과 같거나 이전이면 제외한다. 마감시각이 원천에서 제공되지 않은 후보는 그 이유만으로 제외하지 않는다.

- 정정안은 **이 저장소에만 작성했다.** 중앙 원문이 이미 교정됐다고 표시하지 않는다. 중앙 문서 소유 역할의 개인 담당자·별도 PR/반영 SHA는 미확정이며 외부 메시지/중앙 commit·PR을 이번에 생성하지 않는다.
- 백엔드 관련 공고 조회 소유 역할은 현재 source/배포/실제 응답의 대응을 확인한다. 프론트 DEV-61 실행자는 이 로컬 확정 정책 v1을 자신의 Gate에서 적용한다. 중앙 반영 대기를 실제 API 통합 PASS나 서버 변경 승인으로 해석하지 않는다.
