## 착수 전 Implementation Brief / 설계 Gate

2026-10-28 KST 사용자 요청과 두 범위 답변에 따라 아래 Gate를 확정하고 편집 전 commentary로 제시했다.

- 요구사항: AUTH-01~06과 AUTH-17 중 인증 화면을 현재 실제 API/브라우저에서 검증한다. 과거 17건 대기·부분 성공은 재사용하지 않는다.
- 성공 기준: Origin/CORS·cookie·flowId·기존 로그인/신규 가입·안전한 복귀·새로고침/만료/로그아웃/경합·세 가지 시작 선택의 현재 실행 증거와 정리 결과, 미실행/차단의 독립 판정, Documentation Update Check·verifier·ai-review를 남긴다. 정의된 필수 검증이 남으면 QA-04 전체 PASS로 판정하지 않는다.
- 범위/수정 파일: 이 기록, WBS README, 기존 `docs/qa/auth.md`, 신규 `reviews/QA-04.md` 및 저장소 밖 비식별 QA 증거. 런타임 구현·패키지·설정 변경 없음. 발견한 제품 결함은 사례·재현·영향으로 기록한다.
- 제외: 회사 검색/소속/등록/문서/초대의 데이터 변경과 QA-05~08 판정, 정식 약관/네이버 등 정책 확정, 다른 Task 구현, 공유 서버 운영/설정·배포·외부 메시지.
- 확인한 파일/패턴: AGENTS·세 Skill/verifier, baseline/workflow/task-cycle, PREP 준비표/기록, auth QA, base/plan/architecture/data-access/harness/ai-failures, package/scripts·CI, auth HTTP/session-controller/Provider·callback/signup/start·복귀 경로·config snapshot. API/mock 공개 Repository 경계·메모리 token·cookie refresh·단일 WBS 상태를 유지한다.
- 승인된 계정/정리: 사용자가 Google에서 직접 선택하는 기존 QA-A의 로그인/refresh/logout, 신규 QA-B 1회 임시 약관 동의 가입. 종료 시 로그아웃, 신규 계정은 테스트 데이터로 잔존 허용. 계정 원문을 요청/기록하지 않는다. 회사 데이터는 변경하지 않는다.
- 승인된 환경: `https://local.mate-bid.com:3000` → `https://api-test.mate-bid.com`. 이번 로컬 HTTPS Next 프로세스 시작/종료, 인증 요청, 브라우저 한정 오류/지연/경합·해제 허용. 다른 프로세스·공유 서비스 변경 없음.
- 단계: 시작 식별/체크포인트 → Node 22.20.0 검사·로컬 HTTPS 실행 → 기존/신규·오류·세션·시작/인증 화면 QA → 브라우저 한정 조치 해제·로그아웃/프로세스 정리 → QA/문서 검증·Review Gate → 목적별 커밋·PR/head CI·조건 충족 시 merge/로컬 fast-forward.
- 검증 명령: 실제 scripts의 `pnpm test`, `pnpm lint`, `pnpm build`, `git diff --check`와 브라우저 QA. Vitest는 Node 계약/HTTP 대역으로 live PASS를 대신하지 않는다. Storybook/UI 수정이 없어 build-storybook은 제외. 문서 링크·79 ID/99 Task·상태/범위·고정 기준선/타 QA 보존도 검사한다.
- 환경/가정: 기본 셸 Node 26.5.0과 pin 22.20.0을 구분해 후자를 실행에 사용한다. `/etc/hosts` 매핑·전용 HTTPS 파일 존재·빈 3000 포트 확인; 키/환경파일 내용 미열람. GitHub 최신 성공 test 배포 이력과 실제 실행 버전 미확인은 구분하며, 안전한 실제 만료·오류 재현을 확보하지 못하면 차단으로 남긴다.
