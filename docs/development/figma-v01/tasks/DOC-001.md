## 착수 전 Implementation Brief / 설계 Gate

- 요구사항: 사용자의 2026-10-27 요청에 따라 기존 79개 보고서를 기준선·WBS·작업별 기록으로 만들고 기존 workflow에 연결한다. 문서화만 승인됐으며 앱 개발은 실행하지 않는다.
- 성공 기준: 원본 79개 ID/근거 보존, 개발·검증·정책 결정 분해와 의존성/완료 기준·차단/재개 기록, 현재/다음 작업 식별, 링크·범위 무결성·Review Gate 통과.
- 범위: `docs/development/figma-v01/**`, 기존 `docs/ai-context/{plan,harness}.md`와 세 Skill의 작업 추적/검사 지침. 기존 `src/public/tests/tools`, 설정/패키지/DB·실제 API 실행·기존 문서 부채의 일괄 수정은 제외.
- 확인한 패턴: AGENTS, feature-workflow/context-audit/ai-review, verifier 역할, package.json, ai-context 문서·QA 목록, 원본 JSON/보고서와 기존 DESIGN의 드리프트. API/DTO를 새로 설계하거나 수정하지 않는다.
- 구현 단계/영향: 고정 스냅샷 복사 → 79개 연결표/99개 기록과 WBS → 재개/검증 규칙 → 기존 진입점/Skill 연결 → 문서 검사와 자체/독립 검토. 실행 코드·활성 하네스 설정 영향 없음.
- 가정: 저장소 Markdown이 관리 원본이고 HTML은 역사적 참조. 기한/추정 공수는 확정하지 않는다. 현재 서버 준비 여부·정식 정책은 후속 작업에서 확인한다. 현재 문서 구축에 blocking ambiguity 없음.
- 검증: 링크·79개 커버리지·ID/의존성/상태·스냅샷 hash·기존 변경 보존·신규 파일 공백/개행·diff-check. 문서 전용이므로 앱 test/lint/build와 실제 브라우저/API 검증은 미실행. 다중 파일/하네스 변경으로 verifier와 ai-review 수행.
