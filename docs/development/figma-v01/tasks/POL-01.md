## 착수 전 Implementation Brief / 설계 Gate

### 2026-11-05 · 요구사항 Gate 사전 점검

- 요구사항: H04/O03의 정식 약관·필수 동의·푸터 공개 정보를 승인 근거로 확정하는 정책 Task다. DEV-01/DEV-02의 구현을 포함하지 않는다. 사용자에게 세 질문을 제시했고 아래 세 미준비/미결 답변을 받았다. **정책 결정의 요구사항 Gate는 미통과**다.
- 이번에 진행 가능한 범위: 최신 Git·선행 결과·현행 소스의 읽기 전용 확인, 미결 정책과 재개 조건 기록, 기존 QA 이력 보존, 문서 검사·context-audit·두 리뷰, 승인된 Git 전달. 이 문서 사전 점검의 검증 PASS를 POL-01 정책 완료로 세지 않는다.
- 정책 성공 기준: 위 완료 기준대로 책임/승인 역할과 승인 원문·버전·적용일·URL, 기존 동의 처리, 푸터 공개 범위·문의 목적지를 근거와 함께 확보해야 한다. 사전 점검 성공 기준은 사용자 답변/소스 관찰/미실행을 구분하고 후속 개발의 선행 미충족·재개 위치를 재현 가능하게 남기는 것이다.
- 수정 대상/영향: [WBS](../README.md), 이 기록, [검토 기록](../reviews/POL-01.md), [인증 QA 인계](../../../qa/auth.md#pol-01-preflight) 4개 Markdown. 실행 코드·설정·패키지·하네스·고정 기준선·coverage·타 Task 기록에는 변경이 없다.
- 확인한 근거/패턴: AGENTS·세 Skill·base/plan/architecture/data-access/harness/ai-failures·workflow/task-cycle·DOC-001·기준선 H04/O03·coverage·QA-13의 다음 Gate 선정 예외·DEV-01/02 선행 조건·auth QA AUTH-02/03·현재 package.json과 아래 소유 소스. 전체 과거 대화나 모든 Task 이력은 읽지 않았다.
- 문서 단계: 현행 관찰/사용자 결정을 기록 → 정책별 미결·재개 담당 역할/조건 명시 → WBS/기존 QA 연결 → 문서 무결성 검증 → read-only verifier와 ai-review → 결과 기록 후 영향 재검증/재검토 → 목적별 commit/push·template/라벨 PR·실제 head CI/병합 조건·정상 merge/로컬 main FF.
- 검증/환경: macOS·KST. 현재 package scripts는 dev/build/start/lint/test/test:watch/storybook/build-storybook이고 독립 type-check/format은 없다. 기본 shell Node v26.5.0, 저장소 .nvmrc와 설치된 Node v22.20.0, pnpm 11.3.0을 구분했다. 이번 Markdown 전용 검증은 Python 3의 링크/anchor·79원본99Task·의존성/상태·고정 snapshot·원래 QA/타 Task 보존·범위/민감 패턴 검사와 `git diff --check`다. 앱 test/lint/build/Storybook·브라우저/API는 실행 코드/빌드 영향이 없어 미실행한다.
- 가정/제외: 정책 작성·법적 판단·재동의 여부/시점·새 API·예외를 추정하지 않는다. 승인 자료가 없다는 사용자 답변을 기록하며, 검색 무결과만으로 자료의 부존재를 입증하지 않는다. 개인정보·비밀값·실제 환경파일은 읽거나 요청하지 않는다. 실제 가입/API mutation·서비스 제어·약관 공개 게시·앱 배포는 실행하지 않는다.

## 정책 차단과 재개 조건 · 2026-11-05

사용자는 같은 대화에서 다음을 명시했다: **“미준비 — 승인 자료 확보까지 정책 차단 유지”**, **“미결 — 기존 동의 전환 정책 차단 유지”**, **“미준비 — 공개 정보와 문의 목적지 차단 유지”**. 질문의 추천안은 승인된 문서/결정 경로를 근거로 삼고 미결 정책을 추정하지 않는 것이었다. 법적 문안·운영 공개·재동의 정책의 신규 승인은 없다.

| 미확보 조건 | 필요한 담당 역할(개인 배정 미확인) | 재개 시 확보할 비민감 근거 |
| --- | --- | --- |
| 콘텐츠 책임/정책 승인 역할 | 콘텐츠 관리·정책 승인 담당 | 책임 범위와 승인 기록 경로. 실명/개인 연락처를 요청하지 않는다 |
| 약관/개인정보/필수 동의 승인 자료 | 콘텐츠 관리·정책 승인 담당 | 승인 원문 위치/불변 버전·적용일·공개 URL·승인 시각과 문서별 적용 범위 |
| 기존 개발/테스트 동의의 전환 방침 | 정책 승인·인증 백엔드 담당 | 이전 동의 대상·재동의 필요 여부/시점·미동의 처리의 승인 결정. 미정이면 그대로 차단 |
| 푸터 사업자 공개 범위·문의 목적지 | 사업자 공개 정보 관리·문의 채널 운영 담당 | 공개 승인 자료 경로·표시 항목 범위·약관/문의 링크 목적지·채널 소유/운영 범위. 개인 정보 원문을 이 기록에 복사하지 않는다 |
| 결정과 현행 동의 계약의 대응 | 인증 백엔드·프론트 검증 담당 | 승인 본문과 requiredAgreements code/version·문서 URL 대응, 기존 동의 방침의 지원 여부와 후속 DEV-01 검증 범위. 소스/API/배포 식별자를 구분하고 새 계약을 추정하지 않는다 |

- 정책 산출물·문서별 버전/적용일·정책 승인자/시각은 아직 미확보다. 위 표는 자료 요청/재개 점검 항목이며 확정 정책이나 법적 필수 항목 목록이 아니다.
- DEV-01은 POL-01의 승인된 본문/동의 방침 전까지 요구사항 Gate·구현에 착수하지 않는다. DEV-02는 POL-01/DEV-01 결과와 승인된 공개 정보·문의 목적지가 필요하다. QA-16의 공개 준비 통합 판정도 완료하지 않는다.
- 다음 Task는 **POL-01 재개** 하나다. P0 공개 준비의 승인 자료가 선행이고 DEV-01/DEV-02는 이를 기다린다. 다른 Task로 진행하는 새 예외는 요청받거나 승인받지 않았다. 기존 QA-01~13 차단·보류·예외는 각각 보존한다.
- 다음 첫 행동: 최신 main/작업트리를 확인한 뒤 이 재개 표와 사용자 제공 승인 자료의 경로/메타데이터를 대조하고, 세 정책 미결과 담당 역할이 해소됐는지 확인해 POL-01 요구사항 Gate를 다시 작성한다. 자료가 없으면 차단 유지. 다음 Task는 이번 대화에서 실행하지 않는다.
