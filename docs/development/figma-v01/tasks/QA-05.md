## 착수 전 Implementation Brief / 설계 Gate

2026-11-02 KST 사용자 요청과 자원/변경 범위 답변을 바탕으로 편집 전 commentary에 아래 조회 한정 계획을 제시했다. 전체 실제 통합 완료 기준은 위 체크리스트대로 유지한다.

- 요구사항: 기존 MCO-01~10 및 AUTH-07~08 중 준비된 자원으로 가능한 회사 조회를 현재 브라우저/API에서 검증하고, 미실행·차단·과거 mock/HTTP 대역을 분리한다.
- 성공 기준: 현재 Git/실행 식별자·Origin·브라우저/화면·시각·안전한 Network 요약·UI 결과·정리를 남기고, 없는 상태별 자원과 신청 변경/복구 범위를 차단으로 추적한다. 일부 조회 성공이나 문서 Gate PASS를 QA-05 전체 PASS로 올리지 않는다.
- 범위: 기존 QA-A/QA-B의 로그인/세션 및 회사·신청 조회, 미연결 두 선택지, 승인된 조회 범위의 검색과 입력 화면, 가능한 브라우저 한정 오류/복구·모바일/키보드. 상태는 실제 응답으로 확인하며 별칭만 기록한다.
- 제외: 소속 신청 제출/취소/승인·상태 생성, 회사 등록/수정·DB/fixture·문서/초대·다른 Task, 신규 가입·정책/API 확정·라이브러리 추가·공유 운영/배포·외부 메시지. 회사 간 통합과 소속 신청은 구분한다.
- 확인한 패턴: AGENTS·세 Skill/verifier·baseline/workflow/task-cycle·PREP 준비표·QA-04 완료/승인·QA-03 제한 종료/인계·my-company/auth QA·base/plan/architecture/data-access/harness/ai-failures·package/CI·company HTTP overview/search/context·회사 UI/신청 입력. 공개 Repository 경계, refresh→companyContext 또는 신청 GET, 404/CR001만 빈 상태, WBS 단일 상태를 유지한다.
- 수정 파일: 이 기록, WBS README, `docs/qa/my-company.md`, `docs/qa/auth.md`, `docs/qa/README.md`, `reviews/QA-05.md`와 저장소 밖 비식별 증거. 후속 서버 출력 사건 확인 후 commentary로 `docs/ai-context/ai-failures.md`의 사건/방지 규칙 추가를 제시했다（외부 `scope-addition.json`）. 런타임·설정·패키지·테스트 코드는 변경하지 않는다.
- 단계: 시작 지문/체크포인트 → 현재 실행/로그인 조건 확인 → 승인된 조회·안전한 UI QA → 소유 브라우저/프로세스·한정 계측 정리 → 사례/차단/다음 행동 기록 → 문서 검증·verifier/ai-review → 통과한 기록의 목적별 커밋/PR·head CI·정상 merge·main FF.
- 검증: 현재 package scripts/Node pin을 확인한다. 소스 변경 없는 기록 검증은 링크·79원본/99Task·사례/상태·의존성·기준선/타 작업 보존·`git diff --check`를 사용한다. 실행한 앱 검사는 실제 명령/결과를 별도로 적고, 미실행을 PASS로 세지 않는다. 실제 API와 브라우저 오류 재현 결과도 분리한다.
- 승인/미결: 사용자 답변으로 QA-A/QA-B만 사용, 나머지 상태는 차단 유지, 조회만 실행·신청 제출/상태 생성 차단을 확정했다. QA-04의 같은 로컬 HTTPS 환경·소유 프로세스/인증·브라우저 한정 재현/정리 승인은 그 범위로 재사용하며 회사 변경으로 확대하지 않는다. 사용자: “현재 실행 버전 자료 없음 — 미확인 유지 (추천)”. backend 실행 버전은 미확인으로 유지하며 소스/현재 응답과 구분한다.
- 위험/가정: 계정 원문·이메일·번호·token/cookie·인증 query·`.env`·개인 키 내용을 읽거나 출력하지 않는다. 상태별 계정/회사 미준비와 실행 버전 공백이 전체 판정을 차단할 수 있다. 검색 결과/신청 context가 개인정보를 포함하므로 허용한 필드·집계만 관찰한다.
