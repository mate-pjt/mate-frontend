## 각 Task의 실행 전 조건

- 실제 환경에는 프론트/서버 실행 버전과 게시 명세 대응, 동일 사업자 identity의 합성 회사 쌍, 원본 신청자·검토자·현재 대표자·무권한/퇴사자, 부수 변경과 종료/정리/복구의 범위와 승인된 담당이 필요하다. 기한 경계는 승인된 테스트 시계/fixture로 확인한다. DEV-37의 실제 사유 조회는 [별도 계약 선행](../development/figma-v01/tasks/DEV-37.md#dev-37-pol-16-handoff)이다.
- 실제 반영과 정리는 승인된 범위를 기록한 뒤 확인한다. 브라우저 폭·키보드와 장애 상태는 기능 검증, HTTP double과 합성 mock은 로컬 검증, 서버의 실제 역할별 read/write는 실제 통합으로 기록한다. 운영 판정·cleanup 실행은 읽기 전용으로 확인할 준비된 결과나 별도 승인된 테스트 절차가 필요하다.
- 사유·메시지와 개인 데이터는 fixture의 합성값으로만 확인한다. 인증 수단·원본 문서·서명 주소를 수집하지 않는다. [검증 공통 규칙](README.md)
