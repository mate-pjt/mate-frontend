## 준비 판정 기준

- **준비**: 해당 자원과 사용/변경/복구 범위가 확인되고 현재 실행 증거를 확보할 수 있음. 이번 점검에서 이 조건을 만족한 QA는 없다.
- **미준비**: 기존 기록에 필요한 자원 부재가 명시됐고 이번 문서 점검에도 이를 해소한 증거가 없음. 현재 서버를 새로 조회해 부재를 확인했다는 뜻은 아니다.
- **미확인**: 과거 관찰이나 구현은 있으나 현재 환경·fixture·승인의 충분한 증거가 없음. 현재 데이터가 0건이거나 서비스가 실패한다는 판정이 아니다.

아래는 **2026-10-28 사전 점검 결과**다. 기존 case의 통과/대기/차단 수, 상태 또는 실행 이력을 수정하지 않았다. 담당 역할은 필요한 책임 구분이며 실제 담당자 배정은 전부 미확인이다. 별칭은 앞으로 준비할 자원의 구분만 뜻하며 생성·배정된 자원이 아니다.

## 조건부 실행 순서와 다음 작업

1. **최초 실제 QA: QA-04.** Origin/CORS·쿠키·flowId·로그인/가입/세션/로그아웃을 먼저 완결해 HOME-09/BID-15와 QA-05~13의 인증 선행 조건을 해소한다. 시작 전 위 계정·변경/복구 결정과 실행 식별자를 확보한다. 실제 요청은 이번에 실행하지 않았다.
2. QA-04가 필수 검증/리뷰를 통과한 뒤 QA-01 → QA-02 → QA-03. 공개 공고 fixture가 준비돼야 하며 각 Task를 완결한 다음 이동한다. QA-04를 먼저 두는 것은 홈·목록의 인증 사례를 미룬 승인 예외를 새로 만들지 않기 위해서다.
3. 그다음 QA-05 → QA-06 → QA-07 → QA-08 → QA-09 → QA-10 → QA-11 → QA-12 → QA-13. 각 작업의 자원·승인·선행 조건을 다시 확인한다. 준비가 안 된 작업에서 자동으로 뒤 작업으로 넘어가지 않고 workflow의 차단/기존 예외 규칙을 적용한다. 이 순서는 현재 자원 준비를 선언하지 않는다.

**다음 대화의 Task: DOC-002.** PREP-01의 준비표/검토가 통과한 뒤 선택할 작업이다. WBS 작업 기반 표에서 다음 P0이고 선행 DOC-001은 main에 반영됐으며, DESIGN.md의 기존 Major 사실 드리프트는 현재 소스와 대조해 다시 확인했다. 실제 QA 자원 공백과 독립적으로 문서 범위를 완결할 수 있다. DOC-002의 첫 행동은 Git/main 동기화 후 해당 작업 기록과 DESIGN.md Accepted Debt를 현재 인증 세션·알림 Repository와 대조해 요구사항 Gate를 작성하는 것이다. 이번 대화에서 DOC-002 편집이나 실제 QA는 시작하지 않는다.
