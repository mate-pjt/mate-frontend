## 기준과 범위

- 정책: [mate-docs 알림 수신 이메일](https://github.com/mate-pjt/mate-docs/blob/main/docs/domain/notification/overview.md#7-%EC%95%8C%EB%A6%BC-%EC%88%98%EC%8B%A0-%EC%9D%B4%EB%A9%94%EC%9D%BC%EA%B3%BC-%EB%A1%9C%EA%B7%B8%EC%9D%B8-%EC%9D%B4%EB%A9%94%EC%9D%BC). 인증 성공 때만 새 주소를 저장·선택한다. 가입 주소로 되돌려도 인증된 대체 주소는 유지한다. 로그인 이메일은 바꾸지 않는다.
- 화면: `/my/settings/notifications`.
- 실제 API: `GET|PATCH /api/v1/me/notification-email-settings`, `POST /api/v1/me/notification-email-verifications`, `POST /api/v1/me/notification-email-verifications/{verificationId}/resend`, `POST /api/v1/me/notification-email-verifications/{verificationId}/confirm`.

- 정적 검증: Node 22.20.0의 `pnpm lint`, `pnpm build`, `git diff --check` 통과 (2026-09-28).
- 테스트 서버의 개발 메일 경계: 백엔드 `NonProductionRuntimeBoundary`와 `docs/MAT-216-runtime-configuration.md`에 따르면 공유 dev SMTP는 Mailpit으로 제한된다. 네이버 등 외부 수신함에 도착하지 않는 것이 예상된다. 테스트 서버 Mailpit 열람 방법은 아직 없다.

## 테스트 항목

### NREC-01 — 가입 주소 기본 상태와 인증 창

- Figma node: [수신 주소 두 선택지, 3139:52615](https://www.figma.com/design/Eayi1SWD8Xq8tGBmlp5SV2/%EB%A9%94%EC%9D%B4%ED%8A%B8-v0.1?node-id=3139-52615)
- API: `GET /api/v1/me/notification-email-settings`
- 준비 데이터: 로그인한 테스트 계정, 인증된 대체 주소 없음.
- 조작: 설정을 열고 `다른 이메일로 받기`를 선택한다.
- 예상 결과: 가입 주소가 선택돼 있고, 대체 주소가 없으면 인증 창이 열린다. 인증 전에는 기존 선택이 유지된다.
- 상태: 통과 (2026-09-28)
- 환경/증거: Chrome에서 실제 설정 GET 이후 가입 주소 라디오가 선택되고 대체 주소가 없는 상태를 확인했다. 다른 주소 옵션을 누르자 인증 대화상자가 열렸고, 기존 선택은 유지됐다. 주소 원문은 기록하지 않았다.
- 결함/담당자/재검증: 없음.

### NREC-02 — 잘못된 이메일 형식

- Figma node: 저장소 이메일 입력 팝업 디자인 패턴.
- API: 검증 단계 전에는 인증 시작 POST가 없어야 한다.
- 준비 데이터: NREC-01 인증 창.
- 조작: `@`가 없는 주소를 입력하고 발송 버튼을 누른다.
- 예상 결과: 브라우저가 형식 오류를 알리고 인증 단계로 넘어가지 않는다.
- 상태: 통과 (2026-09-28)
- 환경/증거: Chrome에 `@` 없는 비실제 값을 입력하자 브라우저의 형식 안내가 나타났고 인증 단계로 이동하지 않았다.
- 결함/담당자/재검증: 없음.

### NREC-03 — 실제 발송·확인·자동 전환

- Figma node: 저장소 이메일 입력·4자리 코드 팝업 디자인 패턴.
- API: 인증 시작 POST, 확인 POST, 설정 GET.
- 준비 데이터: 가입 주소와 다른 본인 소유 테스트 수신함. 사용자가 화면에서 주소와 코드를 직접 입력한다.
- 조작: 인증번호를 발송하고 수신함에서 확인한 코드를 입력해 인증한다. 이후 설정 화면을 새로고침한다.
- 예상 결과: 인증 단계에서 3분 유효시간과 60초 재전송 대기가 보인다. 확인 성공 후 `ALTERNATE_EMAIL`이 선택되고 수신 주소가 새 주소로 바뀌며, 새로고침 뒤에도 유지된다.
- 상태: 대기 (메일 내용 열람 불가)
- 환경/증거: 사용자가 테스트 주소를 화면에 직접 입력하고 발송했다. Chrome에 4자리 코드 입력 화면과 만료 타이머가 나타났다. 이 화면은 발송 API의 HTTP 성공·공통 `isSuccess=true`·DTO 검증을 통과해야 나타나므로 성공 응답은 UI와 호출 코드에서 확인한 추론이다. Network의 개별 HTTP 행은 캡처하지 않았다. 60초 재전송 비활성은 첫 관찰 전에 지나 직접 확인하지 못했다. 외부 네이버 수신함에는 메일이 도착하지 않았고, 백엔드 개발 환경은 Mailpit을 사용한다. 코드를 확인하지 못해 확인 POST·자동 전환은 실행하지 않았다. 새로고침 뒤에도 기존 가입 주소 선택이 유지됐다. 주소·코드·인증 ID는 기록하지 않았다.
- 결함/담당자/재검증: 백엔드 담당자가 테스트 서버 Mailpit의 제한된 열람 방법을 제공하면 새 인증 요청부터 다시 실행한다. 기존 코드는 3분이 지나 만료됐다.

### NREC-04 — 가입 주소로 복귀·인증된 대체 주소 재선택

- Figma node: [수신 주소 두 선택지, 3139:52615](https://www.figma.com/design/Eayi1SWD8Xq8tGBmlp5SV2/%EB%A9%94%EC%9D%B4%ED%8A%B8-v0.1?node-id=3139-52615)
- API: `PATCH /api/v1/me/notification-email-settings` 두 번과 설정 GET.
- 준비 데이터: NREC-03에서 대체 주소 인증 완료.
- 조작: 가입 주소로 전환하고 새로고침한 뒤, 보관된 다른 주소를 다시 선택한다. 테스트 종료 시 가입 주소로 복귀한다.
- 예상 결과: 선택된 주소만 바뀌고 대체 주소는 유지된다. 재선택에 인증 메일이 필요 없고 새로고침 뒤에도 선택값이 유지된다.
- 상태: 대기 (NREC-03의 인증 완료 필요)
- 환경/증거: 인증된 대체 주소가 아직 없어 PATCH 전환은 실행하지 않았다.
- 결함/담당자/재검증: NREC-03 완료 후 실시.

### NREC-05 — 재전송 대기·이전 코드 무효화

- Figma node: 저장소 4자리 코드 팝업 디자인 패턴.
- API: 재전송 POST.
- 준비 데이터: 새 인증 요청과 메일 두 건을 확인할 수 있는 테스트 수신함.
- 조작: 60초 전에는 재전송 비활성을 확인하고, 60초 뒤 재전송한다. 이전 코드를 입력한 뒤 새 코드로 확인한다.
- 예상 결과: 재전송 응답의 새 인증 ID·만료시간으로 화면이 갱신된다. 이전 코드는 거절되고 새 코드만 성공한다.
- 상태: 대기 (Mailpit 열람 필요)
- 환경/증거: 첫 발송 후 확인한 코드 화면에서 재전송 버튼은 이미 활성 상태였다. 60초 비활성 화면은 미관찰이다. 3분 만료 화면은 확인했다. 추가 메일을 만들지 않도록 실제 재전송 POST는 실행하지 않았다. 실제 코드 값은 기록하지 않는다.
- 결함/담당자/재검증: Mailpit 열람이 가능해지면 이전 코드 무효화까지 확인.

### NREC-06 — 만료·오입력 한도·오류 복구

- Figma node: 저장소 4자리 코드 팝업 디자인 패턴.
- API: 확인 POST의 `NE004`·`NE005`·`NE006`, 발송/재전송의 `NE003` 등.
- 준비 데이터: 한도 소진·만료가 테스트 계정에 미칠 영향을 허용한 안전한 별도 인증 요청.
- 조작: 잘못된 코드, 3분 만료, 재전송 대기 및 최대 오입력을 각각 재현한다.
- 예상 결과: 수신 설정은 기존 값으로 남고 서버 오류를 표시한다. 새 인증번호를 받아 복구할 수 있다.
- 상태: 대기 (Mailpit 열람과 안전한 재현 순서 필요)
- 환경/증거: 첫 요청의 3분 만료 뒤 화면에 `00:00`·만료 안내·확인 버튼 비활성을 확인했다. 실제 잘못된 코드·한도 소진·서버 오류 응답은 실행하지 않았다.
- 결함/담당자/재검증: Mailpit 열람과 안전한 재현 순서를 정한 뒤 실시.

### NREC-07 — 실패 시 기존 수신 설정 유지

- Figma node: API 오류 상태는 Figma 별도 화면 없음.
- API: 발송·확인·PATCH의 실패.
- 준비 데이터: 브라우저에 한정된 요청 차단 또는 백엔드가 허용한 오류 재현 조건.
- 조작: 각 요청을 실패시킨 뒤 차단을 해제해 다시 시도한다.
- 예상 결과: 실패한 값을 선택 완료로 표시하지 않고 기존 수신 주소가 유지된다. 복구 후 재시도 가능하다.
- 상태: 대기 (발송 요청의 네트워크 실패만 확인)
- 환경/증거: Chrome에서 인증 시작 URL만 일시 차단한 뒤 비실제 테스트 주소로 제출했다. DevTools의 `Network.loadingFailed`에 `blockedReason=inspector`, `type=Fetch`가 기록됐다. 화면은 연결 실패 안내를 표시하고 입력 단계에 머물렀으며 가입 주소 선택은 유지됐다. 발송 버튼은 다시 누를 수 있는 상태였다. 차단을 해제하고 입력값을 지웠다. 확인·PATCH 실패, 차단 해제 후 실제 재시도, 실제 백엔드 4xx/5xx 응답은 아직 실행하지 않았다. 브라우저 차단 결과를 백엔드 오류로 간주하지 않는다.
- 결함/담당자/재검증: 없음.

### NREC-08 — 인증 전 모바일·키보드

- Figma node: [9.2.0 알림 설정, 3139:52591](https://www.figma.com/design/Eayi1SWD8Xq8tGBmlp5SV2/%EB%A9%94%EC%9D%B4%ED%8A%B8-v0.1?node-id=3139-52591)
- API: 설정 GET. 인증 완료 후 주소 변경은 NREC-04에서 검증.
- 준비 데이터: 390px·320px 브라우저 뷰포트.
- 조작: 두 주소 행과 이메일 입력 대화상자의 가로 넘침·주소 줄바꿈을 확인한다. Space로 다른 주소 선택, Tab으로 입력 이동, 잘못된 주소에서 Enter 제출, Escape 닫기를 확인한다.
- 예상 결과: 390px·320px에서 수평 넘침 없이 주소가 줄바꿈되며, 키보드 조작으로 인증 창을 열고 닫을 수 있다. 잘못된 주소는 제출되지 않고 가입 주소 선택이 유지된다.
- 상태: 통과 (2026-09-28, 인증 전 단계)
- 환경/증거: Chrome 뷰포트 390px에서 문서 가로 폭 390px, 320px에서 가로 폭 305px로 수평 넘침이 없었다. 두 크기 모두 가입 주소가 두 번째 줄로 내려갔고, 대화상자의 `scrollWidth`와 `clientWidth`가 각각 같았다(390px: 356/356, 320px: 286/286). 390px에서 라디오에 Space를 누르면 인증 창이 열렸고 Tab은 이메일 입력으로 이동했다. 잘못된 형식의 비실제 주소를 Enter로 제출하면 브라우저 `typeMismatch=true`로 단계가 진행되지 않았다. Escape로 닫으면 가입 주소 선택이 유지됐다. 320px에서도 창 열기와 Escape 닫기를 확인한 뒤 뷰포트를 원래 크기로 복원했다. 실제 주소가 들어간 캡처는 남기지 않았다.
- 결함/담당자/재검증: 없음.

### NREC-09 — 인증번호 단계 모바일·키보드

- Figma node: 저장소 4자리 코드 팝업 디자인 패턴.
- API: 인증 시작 POST, 필요 시 확인·재전송 POST.
- 준비 데이터: 새 인증 요청을 안전하게 실행할 수 있는 테스트 수신함과 Mailpit 열람 방법.
- 조작: 390px·320px에서 4자리 입력 칸, 타이머, 오류, 재전송을 읽고 Tab/Enter/Escape로 조작한다.
- 예상 결과: 가로 넘침 없이 모든 조작과 안내가 보이고, 인증 전 기존 수신 주소가 유지된다.
- 상태: 대기 (메일 인증 통합 테스트 재개 시 실행)
- 환경/증거: 첫 발송의 코드 입력 화면은 데스크톱에서만 확인했다. 모바일 코드 입력·오류 상태는 새 인증 요청이 필요해 이번에는 실행하지 않았다.
- 결함/담당자/재검증: Mailpit 열람 환경을 확보한 뒤 NREC-03·05·06과 함께 검증.

## 실행 결과 요약

- 통과/실패/차단/대기: `3/0/0/6`.
